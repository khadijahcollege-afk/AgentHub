# AgentHub audit — 15 November 2026

## Verified

- `npm run check`: 142 passed, 0 failed; generated machines synchronized.
- Browser navigation: Studio, Tasks, Notes, Promo, Agents, Gateway, Keys, Skills, Alerts, Settings. No horizontal overflow at 1091 × 936.
- Delegation search narrowed 17 engines to one DeepSeek result; selection counter updated to one.
- Project picker close button dismisses overlay.
- Skills API and UI: 25 local skills discovered; no additional installation.
- Connector heartbeat: `heartbeat-travel` animation running, 2.4-second cycle for connected status. This represents the last health-check state, not a persistent network connection.
- Browser console: no errors after extracting inline PWA registration.
- Final Lighthouse on Studio: accessibility 100, best practices 100, SEO 100; no reported failures. This is not a performance benchmark or a score for every view.

## Changes

- Cross-site mutation requests rejected using Origin / Fetch Metadata checks.
- API responses marked no-store; nosniff, framing protection, referrer policy, and Content Security Policy added.
- Static asset paths checked using resolved paths and directory-relative containment.
- OpenRouter OAuth state included in callback URL, GET callback enforced, pending sessions limited, validation errors returned correctly.
- PWA registration moved to an external script compatible with script-src self.
- Improved recent-session contrast, Continue label contrast, promo touch targets and accessible naming.
- Shared UI references: Linear's navigation/hierarchy and Vercel Geist materials/controls.

## Limits and follow-up

- OpenRouter real account authorization and inference still need a user login; mocked PKCE tests pass.
- Google/GitHub account sign-in has been researched, not implemented.
- Skills share instructions; they do not import MCP connections, logins, or tools from another application. Automatic inline loading uses skill-name matching; the full catalog is offered to the engine.
- Terminal is a command runner, not a PTY; shell state does not persist between commands.
- Screenshot capture was unavailable because the browser tab was not visible to the screenshot service. Browser DOM, computed styles, console, and Lighthouse were inspected.
- Physical phone, alternate viewport sizes, every appearance preference, external integrations and real provider quotas were not exhaustively tested.
- One repeated suite run hit Windows EPERM during config rename. The affected project tests and subsequent full suite passed; no storage workaround was introduced without a reproducible cause.
- Tests and tools are evidence for the checked behavior, not a penetration-test certification.
