## What's new

Two features that answer a question the changes drawer could not: not *what* a run
changed, but *where this code came from*.

- **Commit graph.** A read-only window into history: lanes, merge edges and ref
  chips, read from `git log --all --topo-order`. The layout is computed on the
  server by a pure function, so the client only paints coordinates it is given — and
  the tricky part (lane geometry) is testable without a repository. A parent that
  already owns a rail reuses it instead of opening a second one, otherwise every
  merge would widen the graph permanently. Parents outside the loaded page are
  dashed rather than hidden, because a hidden parent makes a commit look like a
  repository root. Pages are 50 commits, hard-capped at 200 by the server, and lanes
  restart per page: a line connecting to the wrong rail is a confident lie, and a
  graph you cannot trust is worse than a short one.
- **Branch switcher that refuses.** The branch chip in the drawer header lists local
  and remote branches and switches them the way git does: if the checkout would
  overwrite uncommitted work, git refuses, the UI shows the refusal, and your edits
  are still there. Nothing is stashed, nothing is forced. A switcher that silently
  discards edits to make the checkout succeed is worse than one that stops and names
  the file in the way.
- **Per-file patch.** Clicking a file row in the changes drawer now opens just that
  file's patch, taken from the diff already in memory. Right-click offers copy
  relative path, copy full path, and show this file's patch — and nothing else,
  because this app has no editor and no file-manager launch to offer.

There is no commit, push, or reset in this panel, and there is no endpoint for them:
history is changed deliberately from the terminal, not by a button in a drawer.

One bug found while auditing the UI rather than by a test: the graph modal rendered
322px tall out of 748px available, showing 7 of 50 rows. Two causes stacked — `flex:
1` shrinking the body to a zero basis, and a second stylesheet's `.pop` rule
overriding `max-height`, `padding` and `overflow`. Both are fixed at the source.

Validated with 490 tests, including pure layout tests, a real-repository suite, and
HTTP route tests; plus UI audits at 1440/1024/390/320 in both languages. See
[CHANGELOG.md](https://github.com/khadijahcollege-afk/AgentHub/blob/v1.7.3/CHANGELOG.md)
for details.
