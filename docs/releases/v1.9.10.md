# AgentHub 1.9.10

Rotasi Free Auto akhirnya terlihat di layar — dan statistiknya berhenti
menyalahkan model yang sehat.

Rilis ini membawa dua perbaikan yang saling melengkapi. Keduanya berasal dari
satu pengukuran: token pertama model gratis di mesin ini datang pada 11–39
detik, sementara ambang "tanpa output" saat itu 30 detik.

## Bagian 1 — statistik berhenti menyalahkan model sehat

Harness CLI mencatat **setiap** abort sebagai kegagalan:

```js
if (killed === 'abort') { bumpStat(engineId, { failed: 1 }); return reject(abortError()); }
```

Abort itu bisa datang dari tiga sebab yang sama sekali berbeda: pengguna menekan
Stop, run dibatalkan karena percakapan diganti, atau model belum mengeluarkan apa
pun sampai tenggat. Ketiganya tercatat sama. Di mesin ini hasilnya:

```json
"opencode-free-flint-40b-free": { "runs": 1, "ok": 0, "failed": 1 }
```

Padahal Flint menjawab `SIAP` dalam 26,7 detik saat dijalankan manual. Angka itu
menyesatkan ke arah yang paling mahal: orang berikutnya memeriksa modelnya,
bukan ambang waktunya.

Yang berubah:

- **`slow` jadi angka sendiri.** Abort dengan alasan `slow` dihitung `slow: 1`,
  bukan `failed: 1`. Kegagalan sungguhan — exit code bukan nol, CLI tidak
  terpasang, run melewati batas 10 menit — tetap `failed`.
- **Alasan pembatalan dibawa, bukan ditebak.** `AbortSignal.abort('slow')`
  diteruskan ke `killTree()`, lalu ke `abortError(reason)`.
- **UI dan ekspor ikut jujur.** `/api/usage` melaporkan `slow`; baris pemakaian
  menampilkan "N lambat" hanya bila angkanya ada; header CSV bertambah kolom
  `slow`, sehingga ekspor tidak menghilangkan perbedaan yang sudah dibuat di
  layar.

## Bagian 2 — rotasi akhirnya terlihat di layar

Server sudah mengirim event `rotate` sejak Free Auto ada: setiap kali sebuah
model dilewati, server memberi tahu klien model mana yang ditinggalkan dan
kenapa. Klien tidak punya cabang untuk event itu. Di `app.js`, rantai `if/else`
untuk SSE menangani `delta`, `tool`, `subagent`, `approval`, `mode`, `task`,
`done`, `stopped`, dan `error` — `rotate` tidak ada.

Jadi versi 1.9.8, yang justru memperbaiki rotasi di server, tetap terasa sama
bagi pengguna: kirim pesan, lalu "Working" diam 30–75 detik tanpa penjelasan, dan
jawaban akhirnya datang dari model yang tidak pernah disebut. Perbaikan di server
tidak bisa menolong bila kliennya diam.

Yang berubah:

- **Chip status memakai ulang `#chat-tool`.** Tidak ada baris status baru. Saat
  rotasi terjadi, chip menampilkan catatan server apa adanya:

  ```
  SLOW palsu terlalu lama tanpa jawaban (8 dtk) — otomatis coba model lain
  ```

  Angka tenggatnya nyata, bukan tetap: model yang pernah teramati lambat punya
  tenggat sendiri (lihat 1.9.8).
- **Chip dibersihkan saat jawaban mengalir.** Penanda `data-rotate` memastikan
  yang dihapus hanya chip milik rotasi — chip tool biasa tidak tersentuh.
- **Dibersihkan juga saat run berakhir** dan saat chip tool baru mulai.
- **Teks cadangan masuk kamus** ("Mencoba model lain" / "Trying another model").

## Bukti

Perilaku chip tidak bisa dibuktikan dengan membaca kode, jadi diuji di Chrome
sungguhan lewat CDP. Server menjalankan model pertama yang menggantung, memutar
ke model kedua yang butuh 4 detik, dan chip dipantau setiap 80 ms:

```
TAMPIL   "SLOW palsu terlalu lama tanpa jawaban (8 dtk) — otomatis coba model lain"
sembunyi ""
jawaban server: "jawaban dari BB" | engine: opencode-free-bb-free
```

Dua probe pertama gagal, dan keduanya kesalahan alat uji — bukan produk:
model kedua menjawab seketika sehingga chip hanya hidup beberapa milidetik, dan
`ah_engine` disetel setelah `app.js` dimuat (padahal `currentEngine` dibaca saat
modul dievaluasi). Keduanya diperbaiki di alat ujinya, bukan dengan melonggarkan
pemeriksaan.

## Penjaga

- **Statistik** — tes server memeriksa `engine-stats.json` di disk, `/api/usage`,
  dan header CSV. 3 mutasi, 3/3 tertangkap.
- **Kontrak `rotate`** — event harus ada di stream, menyebut model yang
  ditinggalkan, dan datang **sebelum** delta pertama. 4 mutasi, 4/4 tertangkap.
  Satu mutasi sempat lolos karena pemeriksaan lama `/dataset\.rotate/` masih
  cocok dengan `dataset.rotateOff`; regex-nya diperketat menjadi
  `delete \w+\.dataset\.rotate;`.

## Catatan nomor versi

1.9.9 tidak pernah terbit. Perbaikan statistik sudah di-commit di bawah nomor itu,
tetapi belum di-tag ketika cacat chip rotasi ditemukan. Keduanya diterbitkan
bersama sebagai 1.9.10 — bukan dengan memakai ulang nomor 1.9.9 — karena
`index.html` sudah pernah menunjuk `app.js?v=1.9.9`, sehingga nomor itu akan
membuat peramban menyajikan `app.js` lama dari cache.

## Catatan

Riwayat rilis 1.9.8 gagal dua kali karena `build-macos` dibatalkan GitHub sebelum
satu langkah pun berjalan: *"The job was not acquired by Runner of type hosted
even after multiple attempts"* — kapasitas runner macOS habis, bukan kode kita.
Build Windows dan Linux berhasil di kedua percobaan, dan percobaan ketiga
menerbitkan ketujuh aset.

Installer AgentHub belum ditandatangani secara digital. Windows akan menampilkan
peringatan SmartScreen pada pemasangan pertama.

Suite: 673 tes, hijau.
