# AgentHub 1.9.13

Satu tanda kutip yang mematikan mode senyap — dan dengan itu, seluruh pemasangan
otomatis.

## Apa yang salah di 1.9.12

1.9.12 sudah benar soal *niatnya*: elevasi diminta di depan, dan argumen installer
lengkap (`--updated /S --force-run`). Tetapi ketika argumen itu dikirim lewat
`Start-Process -ArgumentList`, saya membungkus **setiap** argumen dengan tanda
kutip:

```js
const argList = installerArgs().map((a) => `"${a}"`).join(' ');
// → "--updated" "/S" "--force-run"
```

NSIS tidak memakai `argv`. Ia membaca `GetCommandLine()` mentah dan mem-parse
sendiri (`Source/exehead/Main.c`, `NSISWinMainNOCRT`):

```c
#define END_OF_ARG(c) (c == _T(' ') || c == _T('\0'))

if (cmdline[0] == _T('S') && END_OF_ARG(cmdline[1]))
  g_exec_flags.silent = 1;   // bug #1076 - just set the silent flag
```

Karakter sesudah `S` harus **spasi** atau akhir string. Dengan `"/S"`, karakter
itu adalah tanda kutip. `END_OF_ARG` gagal, flag senyap **tidak pernah diaktifkan**,
dan installer menampilkan wizard-nya.

Akibatnya persis seperti yang dilaporkan: installer hidup, status di layar
mengatakan "memasang", dan tidak ada yang terpasang sendiri. Bedanya dengan bug
sebelumnya — kali ini ia tidak menggantung diam-diam, ia **menunggu klik**.

## Buktinya

Dibaca dari jendela installer yang benar-benar berjalan di mesin uji, bukan dari
membaca kode:

```
jendela: cls=#32770  judul="AgentHub Setup "
  [Static] "Choose Installation Options"
  [Static] "Who should this application be installed for?"
  [Button] "Anyone who uses this computer (&all users)"
  [Static] "There is already a per-machine installation.(C:\Program Files\AgentHub)
            Will reinstall/upgrade."
  [Button] "&Next >"        ← menunggu klik
```

Itu halaman **kedua** wizard, bukan mode senyap. Sesudah `Next` ditekan, versi
terpasang memang berubah menjadi 1.9.12 — jadi pemasangannya sendiri sehat; yang
salah hanyalah cara memintanya berjalan senyap.

Karena `${Silent}` tidak aktif, `installSection.nsh` juga melewati jalur
`doStartApp` (yang mensyaratkan `${isForceRun}` **dan** `${Silent}`), sehingga
aplikasi tidak dijalankan ulang. Dua gejala, satu sebab.

## Perbaikannya

Baris argumen sekarang mengutip hanya yang benar-benar perlu:

```js
export function startProcessArgLine(args = installerArgs()) {
  return args
    .map((a) => (/[\s"]/.test(a) ? `"${a.replace(/"/g, '\\"')}"` : a))
    .join(' ');
}
// → --updated /S --force-run
```

Tidak ada satu pun argumen kita yang mengandung spasi, jadi hasilnya polos. Path
berspasi tetap dikutip dengan benar bila kelak dibutuhkan.

## Penjaga

Tes baru memasang kembali bentuk 1.9.12 (`"/S"`) dan memastikan suite menjadi
merah — bukan sekadar memeriksa bahwa kode hari ini kebetulan benar:

```
MERAH (bagus) — bug 1.9.12 tertangkap
    ✖ install: /S TIDAK PERNAH dikutip di baris argumen Start-Process
```

Yang dijaga: `startProcessArgLine()` menghasilkan `--updated /S --force-run` tanpa
kutip, skrip PowerShell yang benar-benar dikirim tidak mengandung `"/S"`, dan
argumen berspasi tetap dikutip.

## Catatan

1.9.12 memasang dirinya lewat wizard, jadi mesin uji kini berjalan di 1.9.12 —
versi yang masih memuat bug ini. Pemasangan otomatis baru benar-benar terbukti
pada pembaruan berikutnya, sesudah 1.9.13 terpasang.

Suite: 692 tes, hijau.
