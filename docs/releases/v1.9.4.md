# AgentHub 1.9.4

Pemeriksaan "folder bisa ditulis" sekarang menulis.

1.9.3 memindahkan unduhan ke folder yang bisa ditulis, dan memeriksanya sebelum
78 MB diambil. Pemeriksaannya memakai `accessSync(W_OK)`, yang di Windows
**hanya membaca atribut read-only**, bukan daftar izin (ACL) yang menolak.

Akibatnya, pada folder yang izinnya dicabut — persis keadaan `Program Files`
untuk akun pengguna biasa — pemeriksaan menjawab "bisa ditulis", unduhan dimulai,
dan baru gagal di byte terakhir dengan `EPERM`. Gejalanya sama seperti 1.9.2:
user menunggu, lalu melihat kegagalan tanpa sebab yang bisa ditindaklanjuti.

## Yang berubah

- **`canWrite` membuktikan dengan benar-benar menulis** satu berkas kecil lalu
  menghapusnya, bukan bertanya lewat `access`. `accessSync` tetap dipakai
  sebagai saringan cepat, tetapi jawaban akhirnya datang dari percobaan tulis.
  Berkas percobaan tidak tertinggal, dan kegagalan menghapusnya tidak membuat
  folder dinyatakan read-only.

- **Pemilihan folder unduhan jadi lebih disiplin karenanya.** Di instalasi
  per-machine, server sekarang benar-benar melewati `dist/` di `Program Files`
  dan memakai `dist/` di dalam folder data — bukan mengira yang pertama bisa
  ditulis.

## Catatan

Rilis ini juga lahir dari mesin, bukan dari tes: untuk menirunya di mesin uji,
izin folder dicabut lewat ACL, dan di situlah `accessSync` terbukti berbohong.
Dengan perbaikan ini, rantai penuh diuji ulang pada kondisi terburuk — folder
unduhan bawaan read-only — dan berakhir `verify: ok` dengan berkas 82 MB utuh di
folder data.

Pemasangan pertama tetap perlu satu kali manual: aplikasi terpasang di mesin ini
masih 1.6.13, yang belum punya fitur pembaruan sama sekali.

Installer AgentHub belum ditandatangani secara digital. Windows akan
menampilkan peringatan SmartScreen pada pemasangan pertama.

Suite: 648 tes, hijau.
