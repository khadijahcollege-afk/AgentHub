# AgentHub 1.9.12

Pembaruan yang sudah terunduh akhirnya benar-benar terpasang — dan aplikasi hidup
lagi sesudahnya.

## Masalahnya

Gejalanya sederhana dan menjengkelkan: unduhan selesai, berkas installer ada di
disk, status di layar mengatakan "memasang", lalu tidak terjadi apa-apa. Tidak ada
jendela, tidak ada galat, tidak ada versi baru. Hanya aplikasi yang sama.

Penelusurannya dilakukan dari mesin yang benar-benar mengalaminya, bukan dari
membaca kode. Empat temuan, dan semuanya harus diperbaiki agar pemasangan selesai.

### 1. Installer menunggu dialog UAC yang tidak bisa dijangkau

Aplikasi terpasang **per-machine** (`C:\Program Files\AgentHub`, terdaftar di
`HKLM` dengan `/allusers`), sedangkan installer dibangun `perMachine: false`.
NSIS menentukan mode pemasangan dari registry, bukan dari konfigurasi build:

```nsis
ReadRegStr $perMachineInstallationFolder HKLM "${INSTALL_REGISTRY_KEY}" InstallLocation
${if} $perMachineInstallationFolder != ""
  StrCpy $hasPerMachineInstallation "1"
${endif}
```

Kunci itu berisi `InstallLocation = C:\Program Files\AgentHub`, jadi NSIS
menyimpulkan "all users" dan memanggil `UAC_RunElevated` **di tengah pemasangan** —
hanya pada jalur senyap:

```nsis
${if} $hasPerMachineInstallation == "1"
${andIf} ${Silent}
  ${ifNot} ${UAC_IsAdmin}
    !insertmacro UAC_RunElevated
```

Karena installer diluncurkan dengan `windowsHide: true`, dialog UAC tetap muncul
(`consent.exe` tercatat hidup) tetapi tidak ada yang memberi tahu user bahwa ia
harus menyetujuinya. Proses installer menunggu jawaban itu selamanya. Di mesin uji
ia ditemukan menggantung sejak 07:48 dengan CPU 0,28 detik — tanda jelas sedang
menunggu, bukan bekerja.

Sekarang permintaan elevasi dibuat **di depan**, lewat `Start-Process -Verb RunAs`:
jalur resmi Windows untuk meminta izin, dan satu-satunya jalur yang memang
memunculkan dialog. Hasilnya dilaporkan sebagai `mode: 'elevated'`, bukan
`'silent'` palsu.

### 2. `/S` saja memasang berkas lalu berhenti

Installer assisted electron-builder hanya menjalankan ulang aplikasi bila diberi
`--force-run`:

```nsis
${if} ${isForceRun}
${andIf} ${Silent}
  !insertmacro doStartApp
${endIf}
```

Kode lama hanya mengirim `/S`. Artinya: berkas terpasang, lalu tidak ada yang
hidup kembali. `--updated` juga hilang, padahal template memakainya untuk melewati
halaman dan memakai jalur "tutup aplikasi" khusus pembaruan (tidur sebentar agar
aplikasi bisa keluar sendiri, bukan langsung di-`taskkill`).

Argumennya kini disusun di satu fungsi, dan sama dengan yang dipakai
`electron-updater` resmi (`NsisUpdater.doInstall`):

```js
["--updated", "/S", "--force-run"]
```

### 3. `pid` selalu null, `error` tidak pernah terpasang

```js
const spawn = spawnImpl || ((...args) => import('node:child_process').then((cp) => cp.spawn(...args)));
```

Fungsi itu mengembalikan **Promise**, bukan `ChildProcess`. Akibatnya
`child.pid` selalu `undefined` dan pendengar `error` tidak pernah terpasang —
kegagalan spawn tidak terlihat sama sekali. `spawn` sekarang diimpor statis.

### 4. Status `installing` tidak pernah berakhir

Sesudah installer diluncurkan, status berpindah ke `installing` dan tinggal di
sana. Tombol hilang, unduhan dianggap berjalan, dan satu-satunya jalan keluar
adalah menutup aplikasi. Sekarang `installing` selalu punya batas waktu yang
berbeda menurut mode: menunggu **disk** (senyap) jauh lebih longgar daripada
menunggu **jawaban user** (elevasi). Penolakan UAC juga dilaporkan seketika lewat
kode keluar PowerShell, bukan didiamkan sampai batas waktu habis.

## Yang berubah

- **Elevasi diminta di depan** (`lib/update.js`). Mode `elevated` jujur, dan
  argumen diteruskan lewat `Start-Process -ArgumentList`.
- **`needsElevation()`** (`lib/install.js`) menentukan kebutuhan dari kemampuan
  menulis folder aplikasi — bukti nyata, bukan tebakan dari nama folder.
- **`installerArgs()`**: `--updated /S --force-run`, disusun di satu tempat.
- **`installStall()`**: fungsi murni yang memutuskan kapan "menunggu" berubah
  menjadi "macet", beserta alasannya.
- **`spawn` statis**, sehingga `pid` dan `error` bermakna.
- **Status pemulihan**: `installing` yang macet kembali ke `ready` dengan alasan
  yang bisa dibaca, dan tombol pemasangan tidak terkunci selamanya.
- **UI menyebut izin administrator sebelum user menunggu**, dan membedakan
  "menunggu persetujuan" dari "sedang memasang".
- **Alasan kegagalan pemasangan ditampilkan** saat status kembali ke `ready`.
  Sebelumnya user hanya melihat tombol yang sama persis seperti sebelumnya.

## Bukti

Instalasi nyata di mesin uji, sesudah unduhan 78 MB selesai dan checksum cocok:

```
HKLM\Software\d603354d-…\InstallLocation : C:\Program Files\AgentHub
uji tulis folder aplikasi               : TIDAK BISA
installer diluncurkan                   : PID 18448, cmd: AgentHub-Setup.exe /S
consent.exe (dialog UAC)                : hidup
CPU installer                           : 0,28 s (menunggu, bukan bekerja)
status sesudah 8 detik                  : installing (tidak pernah selesai)
```

Perintah PowerShell yang baru diverifikasi **sah** sebelum dipakai: kedua path
(normal dan berisi kutip tunggal) lolos parser PowerShell, dan argumen tiba di
target sebagai tiga token terpisah:

```
parse OK : C:\Users\…\AgentHub-Setup.exe
parse OK : C:\O'Brien\setup.exe
argumen sampai : [--updated][/S][--force-run]
```

## Penjaga

Sebelas mutasi diuji, dan 11/11 tertangkap:

| Mutasi | Yang gagal |
|---|---|
| jalur elevasi dihapus | 2 tes |
| `needsElevation` selalu `false` | 1 tes |
| kutip tunggal tidak di-escape | 1 tes |
| `onExit` tidak pernah dipanggil | 1 tes |
| `installStall` selalu "tidak macet" | 1 tes |
| mode `elevated` memakai batas `silent` | 1 tes |
| UI tidak menyebut kebutuhan elevasi | 1 tes |
| UI menyamakan menunggu UAC dengan memasang | 1 tes |
| `--force-run` dihapus | 2 tes |
| `--updated` dihapus | 2 tes |
| jalur elevasi kembali ke `/S` saja | 1 tes |

## Catatan

Installer AgentHub belum ditandatangani secara digital. Windows akan menampilkan
peringatan SmartScreen pada pemasangan pertama, dan — pada instalasi per-machine —
dialog izin administrator. Keduanya memang harus disetujui; sekarang UI
mengatakannya lebih dulu, bukan membiarkan user menebak.

Suite: 691 tes, hijau.
